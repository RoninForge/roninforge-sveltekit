## v1.0.0 - 2026-05-15

First release. Pinned to `svelte ^5.55.7` + `@sveltejs/kit ^2.60.1` on Node 24 LTS.

### Notes on the wedge vs the existing community Svelte / SvelteKit rules

The canonical Svelte and SvelteKit rules on cursor.directory pre-date Svelte 5 (released October 2024) and SvelteKit 2 (released December 2023, with `$app/state` added in 2.12). Across `svelte.mdc`, `sveltekit.mdc`, and the various stack-combo files, zero mention `$state`, `$derived`, `$props`, `$bindable`, `$effect`, `$props.id()`, snippets, callback-prop event handling, `.svelte.ts` state modules, `mount()` / `hydrate()`, the SvelteKit 2 no-throw `error()` / `redirect()`, mandatory `cookies.path`, top-level `Promise.all` in `load`, `$app/state`, the `formElement` / `formData` rename in `use:enhance`, or the `paths.relative` default flip. Most still teach `on:click` / `<slot>` / `createEventDispatcher` / `export let` / `writable()` for component state, `$page` from `$app/stores` (deprecated 2.12+), and `throw redirect(...)` (broken in v2). This plugin's `svelte-5-runes`, `svelte-5-events-and-snippets`, and `sveltekit-2-core` rules teach the modern shape; `sveltekit-anti-patterns` rule entries reject the pre-5 / pre-2 forms by name with BAD / GOOD pairs.
